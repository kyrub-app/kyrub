## Cache legado — gate local não destrutivo e plano de corte
Piloto mantém Firestore em memória e valida o projeto efetivo do app. Antes de qualquer operação de dados da API e antes de entregar a resposta à UI, enumera somente os nomes de bancos IndexedDB e verifica service workers da origem. Lock permanece permitido para revogar sessões. Uma resposta de unlock barrada por storage tenta revogar a capacidade criada. Não apaga dados, bancos, workers ou armazenamento real. Este gate **não prova** ausência de dados copiados previamente, de caches em outras origens/dispositivos ou de versão antiga que reabra o cache depois da verificação; não é atestado para produção.

### Procedimento de homologação local (somente dados descartáveis)
1. Usar perfil de navegador exclusivo de testes e origem localhost, com Auth e Firestore emuladores e projeto kyrub-security-test. Não reutilizar perfil com dados operacionais.
2. Sem bancos Firestore persistentes e sem service worker da origem, iniciar cliente com VITE_KYRUB_FIREBASE_EMULATOR_E2E=true e VITE_KYRUB_SOCIAL_MEMORY_CACHE_E2E=true, servidor com KYRUB_RESERVED_TRIBE_PILOT=true.
3. Criar fixture de cache legado no mesmo perfil de teste usando cliente persistente; fechar todas as abas sem dados reais, abrir piloto e comprovar bloqueio antes de enviar credenciais à API. Repetir com worker de teste e com enumeração indisponível.
4. Descartar exclusivamente o perfil de teste e repetir o fluxo em perfil limpo; confirmar ausência de fallback, bloqueio de sessão, reload, múltiplas abas e nenhuma escrita em projeto real.
5. Testar fixture de escrita operacional pendente em ambiente descartável: a recusa do piloto não pode apagar ou confirmar a escrita. Sincronizar pelo cliente antigo e conferir servidor antes de descartar o perfil de teste.
