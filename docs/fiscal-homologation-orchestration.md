# Fiscal homologation orchestration

This boundary is sandbox-only and owner-only.

## Prepare

`POST /api/store-connections/fiscal-homologation/:storeId/orders/:orderId/prepare`

The browser supplies only the canonical order id. The server re-resolves the owner/canonical store, reloads the structural homologation policy and canonical payment evidence, creates or reuses the deterministic fiscal attempt, freezes the provider-neutral fiscal document source snapshot, loads the effective explicit tax execution policy, and binds that exact policy version into a ready snapshot.

Prepare does not access provider credentials and does not call Focus, SEFAZ or a prefeitura.

## Execute

`POST /api/store-connections/fiscal-homologation/:storeId/attempts/:attemptId/execute`

This is a separate explicit action. The attempt id must have been generated by the server. The executor re-reads authoritative evidence, loads protected provider configuration/credential, freezes the provider request id and payload fingerprint before the external call, claims the attempt transactionally, and only then submits to the sandbox provider.

No production environment is supported by this route.

## Reconcile

`POST /api/store-connections/fiscal-homologation/:storeId/attempts/:attemptId/reconcile`

This action is allowed only for processing/reconciliation-required attempts. It invokes provider status lookup only. It never reconstructs or resubmits the fiscal payload.

## Authority boundary

The browser cannot supply canonical store id, structural policy/version, tax policy/version, payment evidence, environment, adapter/provider configuration, credential reference or fiscal authority.
