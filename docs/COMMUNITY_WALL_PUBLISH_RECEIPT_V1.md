# Recibo idempotente da publicação comunitária (V1)
Base #1280; issue #1278. ID aleatório reservado wall_UUID, um recibo imutável community_wall_publish_receipts por ID. Transação lê recibo e, se ausente, cria post, recibo e eventual ponteiro Praça atomicamente. Se existente, confere autor/comunidade/hash da solicitação e retorna ID sem escrita. O hash é de comparação, não autorização. Regras exigem recibo novo para IDs reservados e post novo para o recibo. Não permitem alterar/apagar/listar recibos. Leitura de ID ausente autenticada é necessária; outro autor não lê recibo existente (distinção de acesso para ID opaco, sem lista). Recibo preservado mesmo após remoção da origem, evitando ressurreição. Legado não muda.
Rascunho em memória congelado após início de commit; retry utiliza ID e URLs já obtidos, sem novo upload. A saída do rascunho, troca de conta ou reload ainda perde a tentativa local; não prometer idempotência entre dispositivos/reloads. A UI orienta conferir o mural. Não limpa órfãos nem amplia acesso de Storage. Custo incremental esperado: uma leitura e uma gravação de recibo por nova publicação, além de eventual leitura de comunidade e reexecuções; replay uma leitura de recibo, sem escrita. Regras e app precisam de cutover coordenado; não publicar regras de produção, não implantar nem mergear. Teste concorrente no emulador e testes de contrato incluídos, ainda não executados nesta sessão. Avaliar retenção/privacidade do recibo com exclusão de conta antes de ativar; nenhuma expiração automática.
